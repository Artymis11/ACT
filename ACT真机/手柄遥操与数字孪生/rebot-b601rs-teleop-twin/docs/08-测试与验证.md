# 测试、复现与证据范围

## 本公开包的软件检查

迁移到独立相对路径工程后运行：

```powershell
py -3.12 tools/bootstrap.py --teleop-only
py -3.12 tools/check.py
```

结果为 **308项手柄／规划／传输相关Python测试通过，9项数字孪生服务Python测试通过**；此外前端姿态状态回归与JavaScript语法检查通过。

这些测试使用假电机、假CAN传输、临时状态文件或本地HTTP测试服务。不会连接真实机械臂，不需要PCAN DLL，也不发送实机使能／运动／回零命令。

Node.js未安装时，Python检查仍可运行，检查报告明确将Node部分标记为跳过，不能据此宣称前端JavaScript检查已经通过。

## 本地运行命令

完整检查：

```powershell
py -3.12 tools/check.py
```

不接机械臂，使用合成输入与假电机运行控制逻辑：

```powershell
cd teleop
py -3.12 tony_teleop.py --dry-run --scripted-fixture --duration 2
```

只描述入口、验证固定输入来源，不打开任何硬件：

```powershell
cd teleop
py -3.12 tony_teleop.py
```

Node检查：

```powershell
cd digital_twin
node test_pose_state.js
node --check app.js
```

## 已有的历史实机事实

- 真实手柄输入已进入控制目标，并观察过J1实际编码器角变化。
- 曾记录多次B式平滑全零目标结束、A长按返回会话起点结束及复位确认。
- 曾观察输入接近50Hz、MIT平均发送接近200Hz。
- Web页面已读取真实状态文件并呈现七轴角度与模型。

上述事实分别说明对应链路成立；不能互相替代为全臂、全范围、全负载验收。返回目标轨迹与复位确认也不等同精确实测零位验收。
