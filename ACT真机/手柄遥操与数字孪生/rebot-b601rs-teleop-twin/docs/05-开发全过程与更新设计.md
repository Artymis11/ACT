# 开发全过程与更新设计

本文记录从“能读到无线手柄”到“Windows原生遥操＋三维实测监看”的形成过程，按功能阶段整理。这里保留工程决策和可复现内容，不发布个人聊天记录、本机绝对路径或现场控制命令文件。

## 阶段一：确认设备与建立输入层

开始时需要分清三条链路：无线手柄到Windows、USB-CAN到电脑、主电源到电机。手柄已连接并不意味着CAN和电机已经可用，USB已插入也不意味着48V主电源已开启。

输入层采用XInput固定槽位，归一化LX/LY/RX/RY/LT/RT及按钮位。先验证输入和假后端，再接入真实运动链，避免把“网页上某个数字变了”当作实物已经响应。

主要形成：

- 明确的七轴输入顺序和正负号。
- LB按住许可与回中恢复。
- 手柄断连、无效输入与旧采样处理。
- 可重复的假电机回归基础。

## 阶段二：接入手柄设计并完成Windows本地化

本项目借鉴 [Tony 的手柄遥操设计与源码](https://github.com/TonyWeyyy/reBot_B601_rs_xbox_teleop)。

在此基础上，围绕本机实际设备形成Windows实现：

1. 用Windows XInput标准化帧适配北通手柄，明确每个摇杆、方向键与扳机。
2. 固定参考版本和文件哈希，只提取所需输入辅助逻辑，不运行外部项目的硬件生命周期。
3. 通过本机PCANBasic接口统一收发，默认不依赖MotorBridge Gateway或Linux SocketCAN。
4. 将输入、会话、规划、执行、记录分层，避免一个界面同时拥有多套控制器。
5. 增加真实反馈来源与新鲜度约束，区分输入意图、排定目标与编码器实测位置。

## 阶段三：建立“本次起点”的完整生命周期

本次起点的含义固定为：**这一次真正开始控制会话时，读取到的七轴实际姿态**。

它不来自模型默认零点、旧日志、上次运行报告或网页输入框，也不在中途恢复控制时被重新定义。

对应设计：

- X新会话才捕获起点。
- Y返回该起点并继续保持使能。
- A长按3秒返回该起点并结束。
- B使用全零目的地，和A/Y分开。
- 正常结束后监督程序继续等X；下次X重新读实际起点。
- 故障恢复与新建会话分开，不能通过复用旧会话伪造新鲜初始状态。

## 阶段四：修正慢与不连续的控制链

开发中观察到过“动作比预期慢、感觉不够连续”。工程排查发现，早期本地适配把多项阻塞回读放进了输入目标循环，实际输入更新频率降低，却仍按20ms积分，因此额外放慢了目标速度。

最终形成：

- 手柄目标约50Hz；CAN单所有者线程约200Hz发送MIT。
- 七轴目标整组提交，不在一组只更新一半时就作为新目标使用。
- 独立轮询参数，优先更新实际最旧的回执，不阻塞等待整个21项批次。
- 平滑发送在等待响应间穿插进行。
- Windows上使用QPC／`perf_counter`，避免低分辨率时钟影响5ms节拍。
- 调度延误不堆积位移，也不突发补发全部错过帧。
- 保留真实回执时间；新状态快照的发布序号不能冒充新CAN接收证据。

曾有真实运行观察到输入接近50Hz、MIT平均发送接近200Hz。这是测量结果，不是硬实时承诺，也不证明每种姿态都必然平滑。

## 阶段五：故障、日志与恢复分开

几个开发中发现的问题被分别处理：

### 状态文件写入与执行器故障分开

Windows上短时文件占用曾造成原子替换失败。默认遥操分支将此记录为日志写入错误并重试，不再直接把UI文件写入异常升级为执行器故障。

### 手柄仍在线与电机故障分开

即使手柄连接、包号变化正常，控制器也可能因反馈过期或真实电机报警锁存停止点动。因此排错不再把所有“不动”都称为手柄断连。

### 不同报警命名空间分开

保留type2/24状态位与type21完整故障字的来源、原始CAN ID、原始data、接收序号和时间。同样的数字2，在不同命名空间里含义不同；不能脱离报文来源统一解释成过流。

### 反馈恢复与运动恢复分开

只对符合条件的反馈过期问题提供同会话恢复；新鲜反馈、模式、运行状态恢复后，还需要操作者回中并新按X。真实电机故障不自动抹掉，旧排队运动也不补发。

## 阶段六：完成新的四键设计

最终形成现在的操作规则：

| 按键 | 新的交互设计 |
| --- | --- |
| X | 使能新会话／申请恢复 |
| A长按3秒 | 返回本次起点后失能，防止短按直接卸力 |
| B | 平滑回全零后失能，优先覆盖A |
| Y | 只返回本次起点，继续使能 |

同时保留LB按住点动、RB三档速度、120秒无有效操作结束。A长按期间取消点动，输入中断重新计时；Start不再承担恢复；A/X不再与夹爪共用旧按钮判定。

## 阶段七：J2/J3单侧原生零点修正

操作者确认J2、J3从原生0°起向正方向进入工作区。软件采用0～126°，把180°参考跨度的70%放到正确的单侧坐标，而非把一半跨度放在负角区。

这项修正还带来第二个设计要求：**碰到软件工作余量，不应把全臂锁停而无法反向退出。**

因此：

- 软件目标余量只限制相应轴继续向外。
- 同时参考实际位置与排定目标，避免目标仍在内侧但实物已经到边界时继续外推。
- 已越余量起点不瞬间跳回边界。
- 允许反向、其他关节及A/B/Y返回继续使用。
- 不用手动软限位对实测位置做硬故障判断。
- 真实电机或通信故障仍独立处理。

其他轴范围未随J2/J3扩大。详见[专门说明](03-J2J3与单向软限位.md)。

## 阶段八：桌面启动与中文操作流程

从临时命令行调试整理为桌面入口，默认25%档，启动等待X而不自动使能。

公开版进一步采用相对路径与Python自动查找；不再依赖开发者机器上的用户名、缓存解释器位置或训练目录。启动器检测重复遥操进程，不静默杀掉旧会话。

## 阶段九：Web数字孪生监看

加入本地中文三维界面，复用RS URDF与网格，通过现有状态文件获得实际位置。

新增内容包括：

- 实测实体模型与控制目标半透明影子。
- 七轴原生角度对照表和运行信息。
- 旋转、缩放、平移、四种预设视角及键盘操作。
- 暂停画面与继续显示，且不影响手柄控制。
- 数据过期、故障、会话结束及无数据状态。
- 故障期间持续写入日志也不能让最后姿态假装继续实时更新。
- 独立本地只读服务，不新开CAN。
- 桌面／小屏响应式布局和本地资源运行。

## 阶段十：公开版整理

本开源包把上述过程重新整理成可复现工程：

- 清理个人路径、PID、会话ID、故障现场原始日志和控制命令文件。
- 保留实现代码、可复现测试和来源哈希。
- 第三方运行资源首次从固定来源获取，驱动由使用者在本机安装与注册。
- 设备表、按键速查图、详细教程、故障排查、架构导读、CI和上传交接说明。
- 对“已实现”“软件通过”“历史真机记录”“尚未完成的真机验证”分别表述。

## 目前没有扩展成什么

当前不包括完整LeRobot数据集导出、相机同步采集、ACT模型部署、力反馈手柄或物理碰撞仿真。它们可以在明确数据时间、坐标和执行器所有权后继续接入，不能仅凭接口或模型存在就称为已完成实机能力。
