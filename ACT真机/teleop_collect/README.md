# 2. 遥操作与采集

采集通过 SenseCraft Robotics 原厂界面完成。使用 `rebot_arm_102_leader` 主臂与 `seeed_b601_rs_follower` 从臂类型。`front` 绑定顶部 D435i，`wrist` 绑定腕部 D405 并选择 `gripper` 角色。项目的[标定步骤](../hardware/)和[配置示例](config.example.json)可用于重建本机环境。

## 录制步骤

1. 在 SenseCraft 完成设备检查和双摄预览。固定相机位置、红块和盒子摆位，测试手和线缆是否挡住夹爪。
2. 先录一条短样片，回看七轴状态、动作标签、双视频帧和时间戳是否对应。记录写入路径和数据集名称。
3. 正式录制时保持每集包含接近、夹持、提起、入盒、撤爪。补采偏移摆位时按组记，留出集按整集切分。
4. 导出 LeRobot 数据，保留相机键、帧率、实测状态与动作标签的单位。使用[数据处理说明](../dataset/)核对集数、帧数和文件。

## 排查记录

- 主从按键流程曾先遇到设备未就绪（4006），随后在复用本机标定时从臂释放回执超时（2402）。将校准是否存在、PCAN 通道占用、USB 重插后的通信和实际释放分开核验。恢复后确认主从跟随并执行正常释放。
- 两个相机通过 RealSense 序列号固定角色。USB 重插后复查键名、预览画面与视频文件，防止相机顺序交换。
- [teleop_trace.py](teleop_trace.py) 为采集端的可选追踪工具，记录主臂输出、从臂入口与 MIT SDK 调用。历史软件链用 1,499 组主臂样本回放通过 10 项检查。物理验收同时看实际反馈和录像。
- [act_realsense_support.py](act_realsense_support.py) 提供序列号来源解析、相机枚举和预览适配，用于核对两个视角接入 SenseCraft 的契约。

每次采集记一页[工作记录](../docs/session-template.md)，把问题发生的设备环节和更换后的实测结果写下来。
